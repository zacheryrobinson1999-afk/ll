# Manual library V2 implementation

## Audit before implementation

- Web `/docs`: `pages/docs.tsx` has a controlled search input connected to `rankDocuments` and a memoized filter; it is not an inert input. However, seven Recently Added cards and up to four Recently Viewed cards render above the input independently of the query. They remain visible even on zero matches. System/type/equipment filters remain active during search. Only `document` is read from the URL; query and filters are local state and are lost on navigation.
- Web home: `UnifiedSearchBox` is wired to `useUnifiedSearch` and updates local results immediately. It uses the same ranking as `/docs`. `scoreFields` accepts any matching query term, so multi-term queries can return unrelated partial matches. Manual fields omit year and resolved fleet names. Normalization itself already supports punctuation/space compaction.
- Web `/search`: input edits `draft`, but `useUnifiedSearch` consumes URL `query`; only submitting updates that URL. Thus typing does not change the results.
- Mobile `app/(tabs)/docs.tsx`: the controlled input does filter, but with lowercase literal `includes`. It checks trim only to detect empty input, then searches the untrimmed string. It omits summary, document number, year, section references/summary, manufacturer and documentType. Hyphen/space variants fail. System and crane constraints apply before search. All groups expand into full lists. Navigation uses local selected-document state, with no route/back integration.
- Web catalogue re-exports the API static catalogue (73 documents); mobile deliberately has its own existing subset (19 documents). Mobile new records retain extra metadata at runtime but the local type omits it. Keep both inventories and their IDs/URLs unchanged.
- Maintenance/fleet document links have no separate manual search input. Web notes search concerns private workshop notes, not the static catalogue. No native mobile manual bookmarks or recent-document history exist yet; web has local favourites/recent views plus server-backed private bookmarks.


## New manual-library UX

The empty-query view presents compact manufacturer/system cards, then model cards, then manuals. Counts come from the filtered catalogue. Web retains 73 documents; mobile retains its existing 19-document subset. The example counts in the request were not used as catalogue facts.

Typing switches directly to matching manual cards across the full library, overriding manufacturer/model selection. Type and favourites/bookmarks filters still intersect results. Clear-X restores the prior drill-down. Zero matches display an explicit empty state, with no unrelated recent/new cards. Recently viewed is collapsed at the library root; duplicate Recently Added cards were removed from the default view without removing any manuals.

## Search normalization and architecture

Both libraries now use `manualLibrary.ts` and the existing `searchNormalization.ts`. Case, accents, punctuation, hyphens and spaces normalize consistently. Empty/whitespace queries retain the hierarchy; punctuation-only queries return no matches. Partial substrings are supported. The complete compact query may match a field, or every normalized term must match metadata. There is no edit-distance/fuzzy matching and no fallback to all documents.

Fields include title, subtitle, manufacturer/group label, system, sourceSystem, documentType, type, document number, optional book code, year, summary, explicit craneTypes/appliesTo, resolved fleet model/manufacturer, and section references/titles/summaries. Engine identifiers are found where present in those fields. No identifiers are invented.

The web home dropdown and full search page still use existing score-based ranking, but manual eligibility comes from this same shared predicate. Extra metadata feeds the ranking too. Fleet/note ranking is preserved. Manual metadata is local: no per-keystroke manual API request. Existing private-note search remains debounced; responses from an earlier query cannot appear in the current results.

## Manufacturer and model grouping

Manufacturer groups use explicit manufacturer metadata first, otherwise system. Legacy LICCON 1/2 map to Liebherr and ECOS/CCS to Grove. All other labels come directly from catalogue metadata; there is no fixed list of supported brands. Distinct publisher labels remain distinct.

Model groups use only structured craneTypes plus models resolved through explicit appliesTo IDs. Formatting-equivalent labels deduplicate; numbers alone never establish a relationship. A multi-model manual appears in every explicitly supported model group, once per group. Manufacturer counts count unique manuals, so model counts can overlap.

Records without model applicability use Engine documents if their identity is engine-related, otherwise General / system documents. The generic Hino J08E/P11C handbook remains under Hino > Engine documents. The Hino engine parts catalogue supports CKS2500 under its Hino model groups. CKE1800 is never relabelled CKS1800. Broad catalogue labels, such as “Kobelco crawler crane”, are retained as broad groups, not converted into specific models.

## Filter behaviour

Only represented categories appear, in the order All, Operation / Maintenance, Service / Workshop, Parts, Diagnostics, Electrical, Engine, Reference. Categories derive from title, structured documentType and existing type, never incidental words in long summaries. A manual may belong to multiple appropriate categories (for example Engine and Parts). Reference is the fallback when no more specific identity/category is supported. No underlying DocType or document identity was changed.

Search and type filters intersect. Manufacturer/model browsing constrains empty-query results, but typing searches globally. Web favourites and mobile device bookmarks remain explicit additional filters. Counts reflect those active constraints.

## Web changes and preserved workflows

- Search is above results and live on both /docs and /search; clear-X is available.
- /docs query parameters hold q, manufacturer, model, type, favourites and the existing document ID. Drill-down/filter/detail selections create history entries; typing replaces the current entry, avoiding one Back press per keystroke.
- Breadcrumbs navigate hierarchy. Closing details preserves the query/filter context. Existing /docs?document=... URLs still work.
- Cards show title, manufacturer/system, supported models, actual document type, code and year. Long summaries remain in the detail sheet. Open Manual, server-backed Bookmark and legacy Favourite actions retain original IDs.
- Existing section bookmarks and Add workshop note links remain in the detail sheet. Document URLs, local recent-view recording and server-side successful-document activity recording are unchanged.
- Private bookmark storage/API, fleet links, notes, database files and migrations were not modified.

## Mobile changes

The Docs tab uses the same search/group/filter helper over its original catalogue. Touch targets are at least 44px, with wrapping type chips, group cards, breadcrumbs and direct Open manual/Bookmark actions. Expo route parameters hold search, hierarchy, category, saved-only state and selected document; push navigation and router back replace the prior state-only detail navigation.

Native mobile previously had no manual bookmarking or recent-history implementation. New mobile bookmarks/history are explicitly device-local, using AsyncStorage and existing manual IDs. They do not replace or migrate web private bookmarks. All stacked routes share the same state. Existing detail sections and PDF-opening mechanism are preserved.

## Known limitations

- Native Expo was typechecked; a physical-device/emulator run was not performed. Narrow-screen visual inspection was of the responsive web product.
- Preview session/bookmark responses were local fixtures, not live production authentication or database writes. Existing workflow unit tests cover server identity validation and activity triggers; optional database integration was skipped as noted.
- Mobile bookmarks are device-local and do not sync to web accounts. Mobile retains its original 19-document subset; expanding it to the 73-document web catalogue was outside this identity-preserving UI change.
- Category derivation is conservative and depends on existing metadata. Broad model labels are not reinterpreted as exact compatibility.
- Web build emits non-blocking UI sourcemap diagnostics and a >500kB bundle warning (635.54kB main JS). Both builds exit successfully.
